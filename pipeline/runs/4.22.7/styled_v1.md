# Sportshealing Knee Score

This site's own score, described here as the architecture defines it and with
the parts that are not in this repository named rather than filled in.

## For Medical Students

### What It Tests

This score asks about seven things: pain, sleep, swelling, stiffness,
instability, stairs and function. 4.18.6 covers functional limitation.

Those seven are what the architecture specifies, and they are what this page can
describe. 4.1.4 covers the structured approach.

What is not in this repository is the wording of the items, the response
options, the scoring, any weighting between the seven, and any validation work.
None of those is written here, because writing them from memory would invent an
instrument rather than describe one. 4.22.8 covers the use of these scores.

### How It Is Performed

The seven contributors are the ones named above, and each would be asked of the
patient directly.

Pain and sleep together separate a knee that hurts on use from one that hurts at
rest, which is the distinction that marks a later stage. 4.2.13 covers night
pain.

Swelling records the activity of the joint rather than its structure. 4.6.3
covers the effusion assessment.

Stiffness records the capsular and synovial response, which is the symptom that
eases with movement. 4.2.4 covers stiffness.

Instability records the symptom rather than the examination finding, and the two
diverge. 4.2.2 covers instability.

Stairs and function record the activities the patient has lost, which is the
part a treatment decision uses. 4.7.9 covers the functional range.

Administration, scoring and interpretation are not specified in this repository,
so no instruction for them appears here. 4.1.8 covers examination
documentation.

### What a Positive Means

Nothing on this page states what a score means, because no scoring exists in
this repository to read a score against.

The seven contributors each describe a domain, and a profile across them would
be the natural result of an instrument built on them. 4.22.2 covers the KOOS.

Including sleep is a choice the established instruments make differently, and it
is worth noting as a deliberate difference rather than an omission elsewhere.
4.2.13 covers night pain.

Including instability alongside arthritic symptoms spans two populations that
the existing instruments usually separate. 4.22.3 covers the Lysholm score.

Whether that span is a strength or a weakness is a question the validation would
answer and this repository cannot. 4.22.8 covers the use of these scores.

No item count, score range or validation figure appears on this page.
Those are properties of a published instrument and stating one from memory
is the same class of claim as an invented citation, so the page describes
what the instrument does and a reviewer with the questionnaire can add the
numbers.

## FRCS Level

### How Good It Is

At decision level an unvalidated instrument is not used for a decision, and
saying so is the whole of this section.

The seven domains are a reasonable coverage of what an arthritic or unstable
knee costs a patient, which is a content argument rather than evidence. 4.18.6
covers functional limitation.

A validated instrument exists for each of the populations this one spans, so
there is no decision for which this score is the only option. 4.22.1 covers the
IKDC.

If this score is to be used, it is collected alongside a validated instrument so
that the two can later be compared. 4.22.8 covers the use of these scores.

The development work that would change this position is a methodological
project, and naming it is more useful than approximating it. 4.1.8 covers
examination documentation.

### Where It Misleads

The commonest error available here is presenting an unvalidated score as if it
were validated. 4.22.8 covers the use of these scores.

A plausible item list invites the assumption that the instrument works, which is
exactly the assumption validation exists to test. 4.22.2 covers the KOOS.

A score collected without a validated comparator cannot later be interpreted,
which wastes the collection. 4.22.1 covers the IKDC.

Weighting the seven domains by judgement would produce a number that looks like
a measurement. 4.2.10 covers severity.

Using it for a published comparison would misstate what the number is. 4.22.5
covers the Oxford Knee Score.

### Key Learning Points

- Presenting an unvalidated score as validated is the error to avoid.
- A plausible item list invites the assumption validation exists to test.
- A score collected without a comparator cannot later be interpreted.
- Weighting by judgement produces a number that looks like a measurement.
- No decision requires this score.

## Fellowship Level

### Where It Misleads

At fellowship level the interesting question is what it would take for this
score to mean something, and this repository can state the shape of that work
without doing it.

Item generation, item reduction, response scaling, scoring, reliability,
validity against existing instruments and responsiveness are the stages, and
none of them is in this repository. 4.22.8 covers the use of these scores.

The seven domains overlap, so an unreduced item set would double count: sleep
and pain, stiffness and function, stairs and function are each pairs that move
together. 4.18.6 covers functional limitation.

Spanning instability and arthritic symptoms means the instrument would need
validating in both populations, which is twice the work and is the price of the
breadth. 4.22.3 covers the Lysholm score.

A site specific instrument invites the suspicion that it exists to produce
favourable numbers, and the defence against that is published development work
rather than assertion. 4.23.7 covers the medico legal setting.

Until then the honest description is the one on this page, which is seven
domains and no instrument. 4.1.8 covers examination documentation.

No item count, score range or validation figure appears on this page.
Those are properties of a published instrument and stating one from memory
is the same class of claim as an invented citation, so the page describes
what the instrument does and a reviewer with the questionnaire can add the
numbers.

### Key Learning Points

- The development stages are nameable and none is in this repository.
- The seven domains overlap, so an unreduced item set would double count.
- Spanning two populations doubles the validation work.
- A site specific instrument needs published development work as its defence.
- The honest description is seven domains and no instrument.
